# Jed Development Session - October 19, 2025

## Session Summary

Major architectural refactor to introduce pluggable storage for service definitions and environment variables.

## What We Accomplished

### 1. Changed Service Method Signatures (Pointer → Value)
- Changed all Service methods from `*Service` to `Service` (value receiver)
- Methods affected: `Deploy()`, `Undeploy()`, `Redeploy()`, `validate()`, `config()`
- Rationale: Service is small (strings + maps which are reference types), no mutation needed
- **Breaking change** but more idiomatic Go

### 2. Introduced Store Interfaces

**ServiceStore** - Manages service definitions
```go
type ServiceStore interface {
    Get(ctx context.Context, serviceName string) (Service, error)
    Set(ctx context.Context, svc Service) error
    Del(ctx context.Context, serviceName string) error
    List(ctx context.Context) ([]Service, error)
}
```

**EnvStore** - Manages environment variables
```go
type EnvStore interface {
    Get(ctx context.Context, serviceName string) (map[string]string, error)
    Set(ctx context.Context, serviceName string, env map[string]string) error
    Del(ctx context.Context, serviceName string) error
}
```

**Design Decision:** Separated service config from env because:
- Services change rarely (image updates, port changes)
- Env changes frequently (secrets, feature flags)
- Different update frequencies warrant separate stores

### 3. Removed In-Memory Service Cache

**Before:**
```go
type Jed struct {
    client Client
    logger Logger
    svcs   []Service  // Cached in memory
}
```

**After:**
```go
type Jed struct {
    client       Client
    logger       Logger
    serviceStore ServiceStore  // Source of truth
    envStore     EnvStore      // Optional
}
```

**Rationale:**
- Contradicted "stateless" design philosophy
- Could get out of sync with store
- Store IS the source of truth (like "Docker is source of truth for containers")

### 4. Updated API Signatures

**New() - Now accepts stores instead of fs.FS:**
```go
// Before
func (cfg *Config) New(ctx, client, lgr, fs.FS) (*Jed, error)

// After
func (cfg *Config) New(ctx, client, lgr, serviceStore, envStore) (*Jed, error)
```

**Services() - Now queries store (breaking change):**
```go
// Before
func (jed *Jed) Services() map[string]Service

// After
func (jed *Jed) Services(ctx context.Context) (map[string]Service, error)
```

### 5. Added Service CRUD Methods

```go
func (jed *Jed) CreateService(ctx context.Context, svc Service) error
func (jed *Jed) DeleteService(ctx context.Context, serviceName string) error
```

Both methods:
- Validate by querying `Services(ctx)` to check existence
- No cache manipulation (just update store)
- Use modern Go stdlib (`maps.Clone`, map lookups vs index tracking)

### 6. Implemented Built-in Stores

**FSServiceStore** - Read-only filesystem wrapper
```go
serviceStore := jed.NewFSServiceStore(os.DirFS("./config"))
```
- Wraps existing `loadServices()` logic
- Returns error for `Set()` and `Del()` (read-only)

**MemoryServiceStore** - In-memory read-write
```go
serviceStore := jed.NewMemoryServiceStore()
```
- Thread-safe with `sync.RWMutex`
- Used in all tests

**MemoryEnvStore** - In-memory env variables
```go
envStore := jed.NewMemoryEnvStore()
```
- Thread-safe
- Uses `maps.Clone` for defensive copying

## Key Design Principles Established

1. **Stores are source of truth** - No caching in Jed
2. **Standard types in interfaces** - Uses `map[string]string`, not custom types
3. **Separation of concerns** - Service config separate from env vars
4. **Pluggable backends** - Users can implement any storage (DB, Redis, S3)
5. **Stateless** - Query fresh data every time

## Breaking Changes Introduced

- `New()` signature changed (fs.FS → stores)
- `Services()` signature changed (no ctx/error → ctx + error)
- All Service method parameters changed (* → value)
